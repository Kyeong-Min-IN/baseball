# 야구 게임 프로젝트: 백엔드 발표 스크립트

---

### **슬라이드 1-2: 도입 및 목표**

안녕하십니까? 야구 게임 프로젝트의 백엔드 개발을 담당한 OOO입니다. 지금부터 저희 프로젝트의 서버를 지탱하는 백엔드 시스템의 아키텍처, 주요 기능 및 기술 스택에 대해 발표하겠습니다.

저희 백엔드는 크게 세 가지 역할을 담당합니다.

1.  **핵심 비즈니스 로직 처리:** 게임 진행, 승패 판정, 선수 데이터 관리 등 복잡한 게임 로직을 안정적으로 수행합니다.
2.  **데이터 영속성 관리:** 사용자의 계정 정보, 게임 기록, 게시글 등 모든 데이터를 MySQL 데이터베이스에 안전하게 저장하고 관리합니다.
3.  **API 제공:** 프론트엔드(React)와 원활하게 통신하며, 필요한 데이터를 정해진 규격에 맞춰 제공하는 RESTful API 서버의 역할을 합니다.

저희는 **안정성, 확장성, 그리고 유지보수성**을 핵심 목표로 백엔드를 설계했습니다.

---

### **슬라이드 3-4: 시스템 아키텍처 및 기술 스택**

저희 백엔드는 **계층형 아키텍처(Layered Architecture)**를 기반으로 설계되었습니다.

*   **Controller Layer:** 클라이언트의 HTTP 요청을 가장 먼저 받는 진입점입니다.
*   **Service Layer:** 실제 비즈니스 로직이 처리되는 핵심 계층으로, 트랜잭션 관리가 이루어집니다.
*   **Mapper (Repository) Layer:** MyBatis를 사용하여 데이터베이스와 직접 통신하고, SQL을 코드가 아닌 XML 파일로 분리하여 관리합니다.

시스템을 구축하는 데 사용된 주요 기술은 다음과 같습니다.

*   **언어:** Java 11
*   **프레임워크:** Spring Boot 2.7.18
*   **데이터베이스:** MySQL
*   **데이터베이스 연동:** MyBatis
*   **인메모리 데이터 저장소:** Redis (캐싱, 실시간 데이터 처리 등 성능 향상을 위해 사용)
*   **빌드 도구:** Apache Maven

### **슬라이드 5: 주요 기능 - 게시판 (BoardController API 분석)**

다음으로 커뮤니티 기능인 게시판 API를 통해 백엔드의 설계 의도를 설명드리겠습니다.

*   **`GET /api/board` (목록 조회):** 한 번에 모든 데이터를 보내는 대신 **페이지네이션**을 구현하여, 꼭 필요한 만큼의 데이터만 전송함으로써 시스템 전체의 성능과 안정성을 확보했습니다.

*   **`GET /api/board/{id}` (상세 조회):** 게시글 정보와 댓글 목록을 **하나의 API 호출로 묶어서** 클라이언트의 요청 횟수를 줄이고, 페이지 로딩 속도를 개선했습니다.

*   **`POST /api/board` (게시글 작성):** 클라이언트의 요청을 `BoardRequestDto`라는 **데이터 전송 객체(DTO)**로 받도록 설계했습니다. 이를 통해 클라이언트가 악의적인 값을 보내더라도 서버에서는 필요한 데이터만 안전하게 필터링하여 **보안과 유연성**을 확보했습니다.

### **슬라이드 6: 주요 기능 - 핵심 게임 로직 (GameController API 분석)**

이어서 백엔드의 심장부인 `GameController`의 API를 분석하여 설명드리겠습니다. `GameController`는 게임의 **생성, 진행, 그리고 정보 조회**의 세 가지 역할을 담당하며, 가장 중요한 설계 원칙은 모든 로직을 **'서버 중심적'**으로 구현했다는 것입니다.

**첫 번째로, '게임 생성 및 준비' 단계입니다.**

사용자가 `POST /api/baseball/game` API를 호출하면, 저희 서버는 즉시 새로운 게임을 생성하고, 상대편 CPU의 라인업까지 자동으로 구성해줍니다. 이는 사용자가 복잡한 설정 없이 빠르게 게임을 시작할 수 있도록 **사용자 편의성**을 극대화하기 위한 설계입니다. 또한, `POST /lineup` API를 별도로 제공하여, 사용자가 원할 때마다 자신만의 커스텀 라인업을 적용할 수 있도록 **설정의 유연성**을 확보했습니다.

**두 번째는 실제 '게임이 진행'되는 단계입니다.**

`POST /pitch`와 `POST /swing` 두 가지 핵심 액션 API를 통해 게임을 진행합니다. 여기서 가장 중요한 점은, 클라이언트로부터는 '어떤 공을 던졌다' 또는 '스윙을 했다'와 같은 **최소한의 행동 정보만 받는다**는 것입니다. 스트라이크, 안타와 같은 모든 결과 판정은 **100% 서버가 담당**합니다.

이렇게 설계한 이유는 두 가지입니다. 첫째, 클라이언트에서의 데이터 조작을 원천적으로 차단하여 게임의 **'공정성'**을 확보하는, 즉 **치팅을 방지**하기 위함입니다. 둘째, 서버가 모든 상태 계산을 책임짐으로써 클라이언트의 역할을 단순화하고 데이터 불일치 문제를 막는 **'상태 동기화'**를 위함입니다.

**마지막으로 '정보 조회' 파트입니다.**

`GET /view` API는 게임 화면에 꼭 필요한 데이터만 담은 최적화된 `GamePlayView` DTO를 제공합니다. 이는 불필요한 데이터 전송을 줄여 **네트워크 성능을 최적화**하기 위한 의도입니다. 또한, `GET /stats` API를 통해 선수의 실시간 개인 기록을 조회할 수 있게 하여, 사용자가 데이터를 분석하는 **부가적인 재미**를 느낄 수 있도록 설계했습니다.

### **슬라이드 7: 결론 및 향후 계획**

결론적으로 말씀드리면, 저희 백엔드 시스템은 모든 핵심 로직과 데이터 판정을 서버가 책임져 게임의 **공정성과 안정성**을 확보하고, 클라이언트와는 최적화된 데이터만을 주고받도록 설계되었습니다.

향후 계획으로는 다음을 고려하고 있습니다.

1.  **WebSocket 도입:** 실시간 채팅 및 게임 상황 중계 기능을 구현하여 사용자 경험을 향상시키겠습니다.
2.  **Spring Security 적용:** 보다 강력한 인증/인가 체계를 구축하여 API 보안을 강화하겠습니다.
3.  **테스트 코드 확충:** 단위 테스트 및 통합 테스트 커버리지를 높여 코드의 신뢰성을 더욱 확보하겠습니다.
